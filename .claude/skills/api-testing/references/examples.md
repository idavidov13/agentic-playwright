# API Testing — Worked Examples

Three end-to-end walkthroughs aligned with the 8-phase `ai-native-workflow`. The phase numbers below refer to `api-testing/SKILL.md`'s in-skill phases.

## Example 1: Adding tests for a brand-new endpoint

User says: _"Add API tests for `POST /api/products`."_

1. **Phase 1** — Source the contract: build schemas and tests from the OpenAPI / Swagger documentation if it exists. Only curl the endpoint first when no documentation is available.
2. **Phase 2** — Create `fixtures/api/schemas/{area}/productSchema.ts` with `ProductSchema` + `CreateProductResponseSchema`, mirroring the documented contract field-by-field. The response envelope (`success / message / data / errors`) is spelled out as a `z.strictObject` per endpoint, not generated by a factory.
3. **Phase 3** — Write the happy-path test using `apiRequest<CreateProductResponse>` and `CreateProductResponseSchema.parse(body)`.
4. **Phase 5** — Add tests per the coverage matrix: 401 missing auth, 403 wrong-role token, 400 empty body, 404 non-existent parent, 405 unsupported method.
5. **Phase 6** — Add `for...of` loops for per-field invalid types and per-field omission; fuzz any path parameters.
6. **Phase 7** — For any mismatch against OpenAPI, add `test.skip` + `// FIXME:` rather than changing the expected status.

Result: a complete `product.spec.ts` aligned with repo conventions and covering every status code the OpenAPI spec lists.

## Example 2: Verifying a multi-step workflow

User says: _"Test the create → get → delete flow for users."_

1. **Phase 3** — Use `apiRequest` inside a single `test`.
2. **Phase 4** — Wrap each of the three calls in its own `test.step('Create user via POST /api/users', ...)`, etc.
3. **Phase 2** — Validate each response against its schema; assert `body` is `null` on the 204 from `DELETE`.

Result: one test, three clearly named steps in the trace, one Zod validation per call.

## Example 3: Locking down validation for a request body

User says: _"We only check empty body — add full validation coverage for `PUT /api/products/{id}`."_

1. **Phase 6** — Add one `test.describe('PUT /api/products/:id - validation', ...)` block.
2. Use `generateProduct()` as the base `validPayload`.
3. For each required field, add a `for...of` loop with the type-specific invalid values from the table.
4. Add a second `for...of` loop that omits each required field via destructure + rest.
5. Add the path-parameter fuzzing loop for `productId`.
6. Assert `BadRequestResponseSchema.parse(body)` on every 400 response.

Result: coverage goes from one empty-body test to N × (fields × invalid-values + fields omitted + path fuzzing) tests.
